## 1. What this phase fixed

`scripts/run-enrichment-live.js` is the **live runner** (NOT frozen, NOT in the
frozen manifest). It previously injected `transport: undefined` into every live
call. The runner built `liveProviderTransport` only through `deps`; with
production `deps = {}` the fallback passed `transport: undefined`, so every
`domainSearch` threw `AGENTDATA_TRANSPORT_UNAVAILABLE` — producing the `failed 1
/ credits_consumed 0 / result_email empty` rows seen on the Verified Leads
sheet. The root cause was in the fallback wiring, not the enriched client.

## 2. Changes

### 2.1 Live transport fallback (default-live-transport)

- Module-level `liveProviderTransport(url, options)` (~365) mirrors the
  client's `fetchTransport(url, options) => Promise<{ status, body }>` contract:
  omits empty headers, then `body = await response.json().catch(() => null)`.
- Fallback at the client-construction site (~697): any `transport` that is not
  a function is replaced by `liveProviderTransport`. An injected
  `deps.client.transport` (tests) still wins; production `deps = {}` now lands
  on the real fetch-based transport instead of `undefined`.

### 2.2 `buildRunOutcomes` (per-lead outcomes merge)

- `buildRunOutcomes({ enrichedRows, skippedRows, failedRows })` (~911) merges
  the three buckets into one surface sorted by `String(lead_id).localeCompare`
  ascending.
- Enriched entries carry `email_source`
  (`lead.email_source || lead.contact_source_provider || provider`),
  `result_email`, `result_verified` (`email_verified === 'Y' ? 'TRUE' :
  'FALSE'`), and baseline `wrote_vw: false` (the write-loop mutation in the
  engine is preserved, ~775-777). Skipped entries carry
  `{ enrichment_skip_reason }`; failed entries carry
  `{ enrichment_failure_reason }`.
- `result_email` matches `SENSITIVE_KEY_RE` → redacted to `<redacted>` in
  reports (deterministic safe-surface behavior, matching existing report
  redaction); `result_verified` is unaffected. `email_source` is NOT redacted
  (it's `hunter | oss | manual`, not a credential).
