## 1. Where the policy lives

The contact country policy is `isCountryInScope(country, { allow, deny })` in
`scripts/run-enrichment-live.js` (NOT in `src/`). The policy deliberately lives
in the runner because `src/enrichment-schema.js` is a FROZEN manifest artifact
and must keep shipping the byte-identical `US_COUNTRIES` / `isUsCountry` used by
the built workflows. The normalization layer is added alongside it in the same
runner:

- `COUNTRY_ALIASES` — the alias table (H.9.2 section 1).
- `normalizeCountry(value)` — trims, uppercases, then maps common variants to
  their ISO-3166 alpha-2 equivalent; unknown values pass through unchanged;
  empty stays empty.
- `isCountryInScope` now runs `normalizeCountry` on the input AND on every
  allow/deny list entry before the existing policy logic (deny wins → `*` /
  empty-allow = allow all → membership). Allow/deny semantics are unchanged.
- `parseCountryList` (used by `readConfig` for `ENRICHMENT_COUNTRIES_ALLOW` /
  `_DENY`) also normalizes through `normalizeCountry`, so config lists are
  canonicalized at the same point.

`normalizeCountry` and `COUNTRY_ALIASES` are exported on the runner module for
tests (export surface additions only; nothing removed).

## 2. The alias table

| Alias (input, case/whitespace-insensitive) | Alpha-2 |
| ------------------------------------------ | ------- |
| `USA`, `UNITED STATES`, `UNITED STATES OF AMERICA`, `U.S.A.`, `U.S.` | `US` |
| `UK`, `UNITED KINGDOM`, `GREAT BRITAIN` | `GB` |
| `CANADA` | `CA` |
| `CA` | `CA` (self-map, canonical form preserved) |

`US` itself is NOT in the alias table — it remains the canonical alpha-2 and is
matched directly. No existing handling was removed; the map only adds aliases.

## 3. Tests

`tests/enrichment-live-runner.test.js` — `isCountryInScope (H.8c country policy)`
suite extended:

- **H.9.2 normalization block** (new): `USA` / `united states` /
  `UNITED STATES OF AMERICA` / `  USA  ` (whitespace) / `U.S.A.` / `U.S.` with
  allow `['US']` → `true`; `UK` with `['GB']` → `true`; `CANADA` with
  `['US','CA']` → `true`.
- **Variants do not leak** (new): `Canada` with `['US']` → `false`;
  `Canada` with `['US','CA']` → `true`; `UNITED STATES` with `['CA']` → `false`.
- **Deny normalization** (new): `USA` denied by `['USA']` → `false`;
  `UK` denied by `['UNITED KINGDOM']` → `false`; `GB` denied by `['uk']` →
  `false` (deny entries are aliased + case-normalized too).
- **Alpha-2 unchanged** (new/updated): `US`/`CA`/`GB` against their own allow →
  `true`; `FR` against `['US']` → `false`. The pre-H.9.2 assertion
  `scope('USA', ['US']) === false` ("exact alpha-2 match, no aliasing") was
  replaced, since aliasing is now the intended behaviour.
- Existing fail-closed (`''`, undefined, null, blank → false), deny-wins, and
  empty/`*` allow semantics are untouched and still pass.
